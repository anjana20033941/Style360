01 Executive Project Summary

1.1 Abstract & Core Vision

Style360 is an innovative, production-grade web platform engineered to eliminate one of e-commerce's most costly bottlenecks: clothing return rates caused by inaccurate fit perception and static 2D product photography. The platform bridges computer vision, generative artificial intelligence, and interactive WebGL 3D computer graphics into a unified browser-based experience.

Unlike conventional virtual try-on systems that merely superimpose flat 2D clothing textures onto arbitrary images (often resulting in unnatural warping, gender mismatches, and severe body part cropping), Style360 features a dual-stage AI intelligence pipeline coupled with an interactive 360-degree 3D avatar viewport.

1.2 The Core Problem Statement

Traditional E-Commerce The Fundamental Defect How Style360 Solves It
Static 2D Images Users cannot evaluate how garments drape around the torso, waist, or back profile. Tripo3D V3 360° Mesh: Generates an interactive 80,000-face textured 3D avatar viewable from any orbital perspective.
High Return Rates (30-40%) Customers order multiple sizes and return ill-fitting or unflattering outfits. Photorealistic FASHN v1.6 VTON: Calculates precise fabric draping, shadow synthesis, and realistic body contact.
Gender / Category Mismatches Users upload male photos for female dresses, producing grotesque AI glitches. Gemini Vision AI Guard: Automated pre-flight validation preventing cross-gender try-ons in ~1.2 seconds.
Body Cropping & Distortion Standard diffusion models crop full-body photos at the knees or warp head scales. Intelligent Pillarbox Resampling: Custom GD algorithm preserving 100% vertical stature and true head-to-body proportions.
Key Viva Takeaway: When examiners ask "What makes Style360 different from an ordinary photo editor or mobile try-on app?", emphasize: We combine photorealistic 2D generative diffusion with single-view 3D mesh reconstruction and zero-overhead WebGL rendering directly in the client browser.

02 End-to-End System Architecture

Style360 is built using a modern hybrid decoupled client-server architecture. The frontend operates as a lightweight, zero-compilation Single Page Interface (SPI) communicating via asynchronous JSON REST APIs with a PHP 8.2 backend gateway. The backend acts as a resilient orchestrator and security proxy connecting to three cutting-edge external cloud AI engines and Cloudflare R2 object storage.

2.2 Step-by-Step User Execution Pipeline

  1. Model Upload & Pre-Flight Validation: User uploads a full-body portrait. Frontend sends image thumbnail to backend/validate_gender.php. Gemini Vision AI inspects biological features vs selected catalog garment. If a mismatch is detected (e.g. male user selecting female evening gown), UI automatically flips or alerts the user with graceful explanation.
  2. Aspect-Ratio Standardization: backend/FalService.php calculates original aspect ratio. If full-body (ratio ≤ 0.68), it applies background-sampled pillarboxing onto a 576x1024 / 768x1024 canvas, ensuring zero limb truncation.
  3. 2D Photorealistic Try-On Synthesis: Request is dispatched to fal-ai/fashn/tryon/v1.6. The model warps the garment according to user posture, synthesizes natural fabric tension, cast shadows, and outputs a photorealistic try-on image (~8-12 seconds).
  4. Automated Background Stripping: FalService::removeBackground() strips noisy studio walls/floors, providing a clean transparent subject to the 3D pipeline.
  5. Tripo3D V3 80k Mesh Reconstruction: backend/generate_3d.php packages the clean subject into an optimized subdivision geometry payload (80,000 polygon limit, PBR enabled) and polls the Tripo task until the .glb mesh is compiled.
  6. Three.js Real-Time Orbit Rendering: Mesh is streamed through backend/proxy_glb.php. Three.js calculates bounding box (THREE.Box3), scales avatar to exactly 1.75m human height, anchors feet at $y=0$, applies 16x anisotropic filtering to all textures, and positions camera to fill 80% of canvas height.

06 Key Engineering Challenges & Solutions

Academic examiners value the candidate's problem-solving acumen. Below are the five most significant technical roadblocks encountered during the engineering of Style360 and how they were overcome.

Challenge 1: CORS Header Absence on Remote 3D GLB Endpoints

The Problem: When Three.js GLTFLoader loaded binary .glb files generated by Tripo3D or hosted on external CDNs, modern web browsers blocked the download due to strict Cross-Origin Resource Sharing (CORS) security policies.

The Solution: Implemented a high-performance streaming CORS proxy in backend/proxy_glb.php. When Three.js requests a model, it requests backend/proxy_glb.php?url=<encoded_url>. The PHP script performs server-to-server streaming with Content-Type: model/gltf-binary and Access-Control-Allow-Origin: *. Furthermore, it caches the binary file locally in temp/glb_cache/, speeding up subsequent model loads by 95%.

Challenge 2: Inconsistent 3D Model Scales & Centering

The Problem: AI-reconstructed 3D meshes arrived with unpredictable coordinate spaces: some models were tiny (0.1 units), others enormous (50 units), some floating in air, and others oriented with Z-axis pointing up instead of Y-axis.

The Solution: Engineered a robust 8-step normalization algorithm in frontend/js/viewer3d.js: 

// 1. Compute raw bounding box & detect Z-up orientation
var rawBox = new THREE.Box3().setFromObject(model);
var rawSize = new THREE.Vector3();
rawBox.getSize(rawSize);
if (rawSize.z > rawSize.y * 1.5) { model.rotation.x = -Math.PI / 2; }

// 2. Uniform scale to exact 1.75m human height
var sf = 1.75 / (rawSize.y > 0.05 ? rawSize.y : 1.0);
model.scale.set(sf, sf, sf);
model.updateMatrixWorld(true);

// 3. Grounding: Center X and Z at 0, place lowest Y vertex at y=0 (podium floor)
var grounded = new THREE.Box3().setFromObject(model);
var gc = new THREE.Vector3();
grounded.getCenter(gc);
model.position.x -= gc.x;
model.position.z -= gc.z;
model.position.y -= grounded.min.y;

Challenge 3: Texture Blurriness & Pixelation During Orbit Rotation

The Problem: When users rotated the 3D model, fabrics appeared blurry, pixelated, and jagged due to default bilinear texture sampling and standard canvas pixel scaling.

The Solution: Applied an advanced graphics pipeline in Three.js:

  • Activated High-DPI Retina resolution: renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2)).
  • Enabled 16x Anisotropic Texture Filtering: tex.anisotropy = renderer.capabilities.getMaxAnisotropy() on all material maps.
  • Configured Trilinear Mipmapping: tex.minFilter = THREE.LinearMipmapLinearFilter and tex.magFilter = THREE.LinearFilter.
  • Enforced sRGB Color Space: renderer.outputColorSpace = THREE.SRGBColorSpace to ensure color accuracy without dark banding.

Challenge 4: Lower-Body Truncation on Full-Body Photos

The Problem: Default diffusion try-on APIs forced square or 3:4 crops, chopping off the legs and shoes of standing users.

The Solution: Built intelligent aspect-ratio detection in backend/FalService.php. If the input image has a tall portrait aspect ratio (≤ 0.68), the system preserves 100% of vertical height, samples the background corner pixel color, and creates a seamless 576x1024 canvas with proportional pillarboxing. Full-body models remain intact from head to toe.

Q1 What is the primary novelty and technical contribution of Style360?

Q2 Why did you use PHP for the backend instead of Node.js or Python?

This eliminates shared-memory leaks and prevents single-thread event loop blocking caused by heavy base64 image decoding. Furthermore, PHP's native cURL handles binary streaming directly to the client without buffering multi-megabyte GLB models into RAM, offering superior memory efficiency.
Examiner Psychology: Don't apologize for using PHP; justify it using systems engineering principles (statelessness, memory isolation, binary streaming).
Q3 How does Style360 solve the CORS problem when loading 3D models?
Model Answer: When Three.js loads GLB assets from external CDNs (like Tripo3D's CloudFront), browsers block the request if the CDN lacks the Access-Control-Allow-Origin header. We solved this by developing backend/proxy_glb.php, which streams binary data through our origin server with full CORS headers (Access-Control-Allow-Origin: *, Content-Type: model/gltf-binary) while caching models on local disk for instant repeat rendering.
Examiner Psychology: Proves you understand real-world browser security models and HTTP protocol nuances.
Q4 Explain the mathematical calculation used to frame the 3D model in Three.js.
Model Answer: We use the vertical field-of-view trigonometry formula. First, THREE.Box3 computes the model's bounding box height ($H$). Given camera vertical FOV $ heta$ in radians: $$ ext{distance} = rac{H}{2 \cdot an( heta / 2) \cdot ext{targetCoverage}}$$ We set $ ext{targetCoverage} = 0.80$, ensuring the avatar consistently occupies exactly 80% of the canvas height, regardless of screen aspect ratio or window resizing.
Examiner Psychology: Examiners love trigonometry and 3D projection mathematics. This demonstrates deep computer graphics competency.
Q5 How do you prevent cross-gender mismatches during virtual try-on?
Model Answer: We implemented a dual-stage validation guard in backend/validate_gender.php. Tier 1 performs regex checks on the uploaded filename in <1ms. Tier 2 resamples the image into an in-memory 320px thumbnail and queries Google Gemini Vision AI. If a mismatch is detected (e.g., male model with female evening dress), the system automatically syncs the UI catalog filter or alerts the user before burning expensive try-on compute credits.
Examiner Psychology: Demonstrates practical safety engineering and cost optimization in AI systems.
Q6 What is Anisotropic Filtering and why was it necessary in Three.js?
Model Answer: Standard isotropic mipmapping samples textures as symmetrical squares. When a 3D model is viewed at oblique angles (such as rotating an avatar's shoulders or waist), textures become severely blurred. Anisotropic filtering samples textures along non-square projections. We query hardware capabilities using renderer.capabilities.getMaxAnisotropy() (up to 16x) to ensure fabric weaves and patterns remain razor-sharp under rotation.
Examiner Psychology: Demonstrates mastery of GPU rasterization and WebGL rendering pipelines.

Q8 What is the role of Cloudflare R2 in this architecture?

Standard cloud providers (like AWS S3) charge heavy egress bandwidth fees ($0.09 per GB transferred). Cloudflare R2 has zero egress bandwidth fees, making it infinitely more cost-effective for serving large 3D graphic assets globally.

Q11 What is the difference between GLTF and GLB formats?
Model Answer: GLTF (Graphics Language Transmission Format) is the JSON-based standard for 3D scenes, but it often references external .bin files for geometry and separate image files for textures. GLB is the binary container format of GLTF: it packages the JSON scene description, binary vertex/index buffers, and embedded PBR texture images into a single self-contained binary file, which simplifies network transmission and streaming.
Examiner Psychology: Proves understanding of 3D asset pipeline formats.

Q14 How are database SQL injection vulnerabilities prevented?

Q15 How does the 3D viewer handle models with Z-up coordinates?
Model Answer: Some 3D modeling packages (such as Blender or CAD tools) treat the Z-axis as vertical height ("Z-up"), while Three.js and OpenGL treat the Y-axis as height ("Y-up"). In viewer3d.js, we compare the bounding box dimensions: if rawSize.z > rawSize.y * 1.5, the model is clearly laying down or exported in Z-up mode. We programmatically apply a rotation of model.rotation.x = -Math.PI / 2 to instantly correct its orientation.

We enabled THREE.ACESFilmicToneMapping with an exposure of 1.1 in viewer3d.js, reproducing the cinematic color response curve used by modern film production and game engines for realistic fabric highlights.

Q21 Is Style360 built using React? Why was Vanilla JavaScript selected over frameworks like React or Angular?
Model Answer: No, Style360 is deliberately built using modern native Vanilla JavaScript (ES6+), HTML5, and CSS3 alongside Three.js and Google's <model-viewer> Web Component. While React is well-suited for traditional corporate CRUD applications, high-performance 3D WebGL computer graphics platforms face critical architectural constraints:

1. Direct Canvas & GPU Memory Control: Three.js operates an imperative 60-FPS animation render loop (requestAnimationFrame) requiring microsecond-level manual disposal of textures, geometries, and GPU vertex buffers. React's Virtual DOM diffing engine adds unnecessary reconciliation overhead and frequent garbage collection cycles, causing noticeable frame drops and stuttering in real-time 3D viewports.

2. Zero Build Overhead & Instant Compilation: Native ES6+ requires zero Webpack, Vite, or Babel bundling steps. It loads instantly in the browser with microsecond DOM updates and zero bloated node_modules dependencies (which typically exceed 200MB+ in React setups).

3. Lightweight Reactive State Architecture: Instead of heavy Redux or Context state managers, Style360 uses lightweight, event-driven state orchestrators (tryonState, window.StudioController) synchronized with browser localStorage, delivering full reactivity with zero framework footprint.
Examiner Psychology: Examiners love to ask this question to probe whether you understand framework trade-offs or merely follow hype. Explaining the GPU memory management and 60 FPS WebGL rendering loop proves high engineering competence.
